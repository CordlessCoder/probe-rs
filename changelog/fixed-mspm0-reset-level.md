MSPM0 targets now restore the instruction prefetcher and both caches after flashing. TI's flash algorithms clear `CPUSS.CTL` when they start and never put it back, and `AIRCR.SYSRESETREQ` resets only the CPU on these devices, so a freshly flashed application ran with flash accesses slowed down until the next power cycle. `probe-rs run` and `cargo embed` now reset through SYSCTL instead, which resets the peripherals too. A bare `probe-rs reset` still uses the CPU-only reset, so `probe-rs download` followed by a separate `probe-rs reset` does not restore them.
